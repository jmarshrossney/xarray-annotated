## Gotchas

- **No `from __future__ import annotations`** — stringizes annotations, so `get_type_hints` re-evaluates them at decoration; markers survive at module scope, but a function-local alias or `TYPE_CHECKING`-only name raises `NameError`. Not silent, and Python 3.14's deferred annotations do not lift the `TYPE_CHECKING` case.
- **pint registry is process-global** — `use_cf_units()`/`set_registry()` is one-time startup; two registries can't mix. Tests isolate per test via `conftest.py:_isolate_registry`.
- **No global behaviour config; `enabled` is the only behavioural global** — the registry is process-wide too, but decides only which units parse. Don't add a `set_policy`, a per-axis env var, or anything else that changes behaviour away from the signature: a process-wide setting can loosen checks with nothing at the definition site to show it (guarded by `test_public_api.py:TestNoGlobalBehaviourConfig`). The switch is root `_config.py`: an `xra.enabled(...)` block (a `ContextVar`, so no test isolation needed) beats `XARRAY_ANNOTATED_ENABLED` in both directions. Off is total: no checks. `units.convert` is not a check, so it ignores the switch.
- **A value that is not a `DataArray` raises `TypeError`, unless the hint allows it** — `_refuse_other_value`, reading `Declared.others`, which holds what the hint's union allows besides a `DataArray` and takes no part in equality. `| None` allows `None`, and any other member allows anything else, unchecked, since a member may be `list[int]`. A record return is held to the same rule, with a missing required `TypedDict` key raising; `__required_keys__` is what tells it from `NotRequired`, as both read to `None` with `.get`.
- **Every failed check raises; there are no severity settings** — no `on_mismatch`, no `on_uninferable`, no warnings (`test_public_api.py:TestEveryFailedCheckRaises`). A softened marker reads the same as a checked one to everything downstream, including `dtype_compatible`/`freq_compatible`, and softening `Freq` also let through arrays with no time axis. To tolerate something, correct or remove the declaration; prototyping uses `xra.enabled(False)`.
- **`check_freq` tests every axis, so nothing is "uninferable"** — 3+ points: `infer_freq`, with `None` a mismatch, as irregular spacing contradicts any declared frequency. 2 points, `gaps_ok` and any-day spellings: `_step_mismatch` compares step by step, passing only a 2-point axis under a business-day or custom offset. 0–1 points pass. `infer_freq` drops the weekday on cftime (`7D`, not `W-WED`), hence `_on_declared_weekday`.
- **`Freq(..., gaps_ok=True)` and `Freq("month")` are declarations, not softened checks** — each says something different at the signature, and a plain `Freq("D")` still means a regular axis. The smallest step must equal the declared one, because whole multiples alone would let every midnight-stamped axis pass `Freq("D", gaps_ok=True)`; the cost is a loud false alarm on daily values with no two adjacent. `gaps_ok` is refused on an opaque or non-positive step (`assert_valid_freq`, and again in `check_freq`), which would otherwise pass unchecked. `freq_compatible` ignores it and stays symmetric, so it does not prove an edge safe. `.freq` is no longer always a pandas alias, so go through `_declared_spacing`, not `to_offset`. See `docs/adr/0002-sampling-period-and-calendar-steps.md`.
- **Audit trail is `logging`, never a mode or a warning** — the only logger is `xarray_annotated.units`, at DEBUG, for every `units.convert`. Never log at WARNING+ (`test_logging.py:TestQuietByDefault`).
- **`enforce` is check-only** — `check_units`/`check_output_units` return the object they were given, so the body gets what the caller passed and the caller gets what the body returned, identically under `enabled(False)` (`test_enforce.py:TestChecksChangeNothing`). No dequantifying, respelling, encoding changes or write-back. Dequantifying was left over from when inputs were converted. A quantified array behaves differently from a plain one, as `rh / 100` on `percent` is `0.6 %`; choosing pint is the user's decision, not `enforce`'s. One consequence: `pascal + Pa` in a plain body loses its label, because xarray drops conflicting attrs, and the output check raises.
- **`units.convert` returns the same kind of array it was given, and an equal unit never converts** — a quantified array stays quantified, a plain one stays plain. `_stamped` is `da.copy(deep=False)` + restamp, sharing the buffer; a quantified array in the unit also shares it. Converting copies it, for nothing when the values do not change. `convert` is the only thing that respells a label.
- **`units.convert` never touches coords** — it goes through `Quantity(magnitude, have)`, not `da.pint.quantify()`, which also parses every coord's `units` attr, so a `degrees_north` label would abort the conversion. `quantify({coord: None})` is no way out: it deletes the coord's label.
- **`Freq.freq` stores raw string — never normalise** — pandas `to_offset("W").freqstr` silently becomes `"W-SUN"`. Raw spelling preserves anchoredness. Never store/compare normalised `freqstr`.
- **Only a coord with a `PandasIndex` is a time axis** — `_is_datetime_like` asks `da.xindexes`, so `check_freq` never reads the disk, and scalar, 2-D and aux datetime coords never compete with the real one. A custom index on the axis is a mismatch, as it may leave the coord lazy (`test_temporal.py:test_custom_index_on_the_axis_is_refused_unread`). Errors name the coord and its fix from dtype, shape and index alone (`_why_not_axis`), which is why an unindexed cftime gets generic wording. Never value-based cftime detection or `da.indexes`: the first reads every unindexed object coord, the second casts every index to pandas and raises on a custom one.
- **Mismatch errors are never `ValueError`** — `UnitError`/`SchemaError`/`FreqError` extend `ContractError` (root `_errors.py`, so domains import it without a cycle), which extends `Exception` directly. A malformed declaration raises `ValueError`, at decoration under `enforce` and first thing in `check_declared`, `check_units` and `check_output_units`, so catching a mismatch never swallows a declaration error. `enforce` calls the private cores (`_check_valid_declared`, `_check_output_unit`), so it validates once. `quantify` and `convert` are operations and keep raising `ValueError` and `pint.DimensionalityError`, so `_own_unit` takes the exception type from its caller.
- **Declarations never convert; `units.convert(da, unit)` does, at the call site** — a compatible-but-different input unit raises `UnitError`. No marker setting, `enforce` keyword or global: whether a conversion is correct is a property of the quantity (`g m-2 yr-1` vs `g m-2 d-1` is compatible and wrong), and a body that relied on one would change results under `enabled(False)`. Same-unit respellings always pass. Adding automatic conversion later breaks nothing; removing it does.
- **`units.convert` clears `.encoding`, on the array only; `enforce` does not** — packing such as `scale_factor` described the old values and overflows on write, silently corrupting the file. `encoding = {}`, not `drop_encoding()`, which also clears coords. `.pint.to` keeps encoding, and a check leaves it, so `units.dequantify` clears it, as `.pint.dequantify()` does not (`test_netcdf.py:test_pints_own_dequantify_corrupts_a_stale_packing`).
- **`check_units` on dimensional mismatch always raises** — no policy knob; always raises `UnitError`, from the pint error. It is not a `pint.DimensionalityError`, which is a `TypeError`, and a pickle drops `__cause__`, so the message carries both dimensionalities (`test_units.py:TestUnitError`). So does a missing/unparseable/over-long input unit: no `on_missing` axis, no `UnitsWarning`, by design — a never-checked declared unit is indistinguishable downstream from a checked one; prototyping uses `xra.enabled(False)`.
- **Quantified arrays are read via `_quantified_units`, never attrs or `.pint.units`** — a `Quantity` holds its unit in the data and has empty attrs. `.pint.units` goes through `da.data`, which reads a whole lazily opened variable from disk, so the helper asks `da.variable._data` instead (`test_units.py:TestLazyArrays`). `attrs` never wins: `quantify()` *raises* ("Cannot attach units") when a leftover attrs label disagrees, so reading attrs first breaks the pipeline. See `notes/logs/2026-07-31-quantified-arrays.md`.
- **`units.quantify` leaves coords plain, so bare `.sel` labels keep working** — `.pint.quantify()` also quantifies coords, which pint-xarray supports through `PintIndex`, with `Quantity` labels. A bare label counts as dimensionless, by design: it raises on metres, but on degrees or percent it converts, so `.sel(lat=20.0, method="nearest")` silently selects the wrong row (`test_units.py:test_pint_xarrays_own_quantify_expects_quantity_labels`). `quantify({coord: None})` is no way out, as it deletes the label. `units.quantify` raises on a missing label, returns a quantified array as itself, and reads a lazily opened array unless dask backs it. Its pair `units.dequantify` spells labels through `_label_format`: CF only when `use_cf_units` is active, as CF spelling does not parse on a plain registry and pint's `"cf"` format depends on `cf_xarray` having been imported.
- **`_is_dataarray_type` accepts `array_type` wrappers — never import jaxtyping** — the check is duck-typed so the composition stays structural; a real import would make it a hard dependency (guarded by `test_public_api.py:test_integrations_are_never_imported`). Hence jaxtyping/beartype sit in the **`integrations` dependency group**, not an extra — nothing to install to "enable" it, unlike the `cf` extra which really is imported. dask and netCDF4 sit there too, for `test_dask.py` and `test_netcdf.py`. jaxtyping's dim strings are positional *size symbols*, not xarray dim names, so `Dims` is not redundant with them.
- **`Dtype("float64")` means `float64`** — no `exact=`, as a marker must mean what it reads. A name with no width (`_KIND_NAMES`) means the kind, though numpy reads it as one dtype; byte order is never compared, as it says nothing about the values (`_same_dtype`).
- **At most one marker of each type per hint** — `_annotations._single_marker` makes `declaration_from_hint` raise `ValueError` on a second `Unit`/`Dims`/`Dtype`/`Coords`/`Freq`, which is what makes `Declared`'s one-slot-per-type shape lossless. Don't relax it to first-wins or collect-all; merge `Coords` names into one marker instead.
- **`enforce` refuses a declared `*args`/`**kwargs`** — the bound value is a tuple or dict, so the declaration could never be checked. It raises at decoration rather than expanding them; the reader still reports them, as they are what the signature says.
- **`enforce` refuses a marker it cannot apply** — a marker inside `tuple`/`list`/`dict`/`Callable`, on a non-`DataArray` base, or in a generic alias (`type F[T] = Annotated[T, Unit("Pa")]`) raises at decoration (`_refuse_stray_markers`): someone wrote it expecting a check. So does a parameter, return or field holding a class whose fields carry markers, when `_walk_signature` does not read it (any parameter, `NamedTuple`, `list[R]`, `R1 | R2`, a record nested in a field; `_refuse_unread_fields`); it reads one return record, one level deep, through `| None`, aliases, `Annotated` and generic parameters. The reader still returns `None` for these. Only the non-`DataArray` half of a partly declared union remains silent.
- **The reader sees through unions, `type` aliases and `TypedDict` qualifiers** — `Annotated[DataArray, ...] | None` and `NotRequired[Annotated[...]]` declare, as `Annotated[DataArray | None, ...]` always did. Two declared union members raise `ValueError`. A new wrapper in `typing` needs adding to `_reader._QUALIFIERS`, or it silently declares nothing. `Annotated[Alias, Dims("x")]` merges the markers of a `type` alias in the base slot, inner first (`_flatten_aliases`), since `Annotated` only flattens a nested `Annotated` itself. An alias that contains itself outside a container raises `ValueError` (`_enter_alias`, a per-path set, since one alias may legitimately appear on two branches). A generic one (`type G[T] = G[T] | None`) is not entered, so it reads as nothing, and `_strip_return_hint` needs its own guard against it.
- **`Unit` has no settings** — `check_units`/`check_output_units`/`convert` take `str | Unit`, and `annotate` takes a string as a writer convenience, but a hand-written annotation always spells the marker.
- **One reader, at the root** — `declaration_from_hint`/`declarations_from_signature` return `Declared`, which keeps the markers. Domains export no readers (`test_public_api.py:TestReaders`). `_reader.py` is the only code that turns `Annotated` metadata into a declaration; `_annotations.py` and `_enforce.py` also walk hints, to find a return's record and to refuse stray markers.
- **Outputs must already match; nothing is stamped or converted** — the author controls the return, so a different, missing or unparseable unit raises, in one rule with no setting. No `on_output`, no `stamp`: the package cannot tell a stale label (`p * 100` keeps `hPa`) from a true one (a forgotten conversion), and a false alarm is loud where a mislabelled result is silent. A correct body that changes the unit computes on `units.quantify(...)`; `.assign_attrs(units=...)`, taken on trust, is for values from outside pint; see #26. A labelled output must never convert: a stale label would apply the arithmetic twice. An optional return is written `| None`; see below.
- **`Unit` stays exact, and docs recommend plain arrays between functions** — a body quantifies the inputs it computes with and returns `dequantify(convert(result, unit))`; a body with no unit arithmetic stays plain. Don't add a dimension-only marker or show quantified arrays crossing a boundary as the default: a check cannot see whether a body stays in pint, and a plain body handed a quantified array can silently change its answer. Quantified arrays stay supported. See `docs/adr/0001-exact-units-plain-arrays-between-functions.md`. On dask, `rolling` and `ffill` lose the unit silently (`test_dask.py:TestOperationsThatLoseTheUnit`).
- **A string in `Annotated` is a description, in every domain** — ignored without error, so `Annotated[DataArray, "Pa"]` declares nothing (`test_enforce_units.py:test_bare_string_declares_nothing`). Only markers declare.
- **`just docs` reporting a failed notebook cell is expected** — `examples/notebook.py` demonstrates a `UnitError` by raising one, so marimo prints "Export was successful, but some cells failed to execute" and the export continues. Not a regression; don't "fix" the example. Check a stashed tree before treating any docs failure as new.

## Design steers

- **New domain facet: touch `_writer.py`, `_reader.py` and `_enforce.py`** — `annotate()` writes facet values → `Annotated`; `declaration_from_hint()` reads one hint → `Declared` (add a slot), which `declarations_from_signature()` drives over a signature. Round-trip exact. In `_enforce.py`, add its check in the wrapper *after* units on both sides; it raises on failure, with no severity setting or `enforce` keyword. Re-export its marker from the root `__init__.py`. No per-domain decorator.
- **New property within domain: follow existing patterns** — Schema's `_CHECKERS` dict dispatches marker type → checker; additive via registry. Each domain mirrors layout: `_annotations.py` / `_check.py`, flat re-export via `__all__`.
- **`_walk_signature` is the shared reader kernel, and private** — `_annotations._walk_signature(func, extract)`. `extract` turns one `Annotated` hint into a payload or `None` (`declaration_from_hint` for the built-in facets); handles `TypedDict`/dataclass/single return shapes once.
- **One decorator, `enforce`, in `_enforce.py`; units always first** — inputs: `check_units`, *then* `check_schema`/`check_freq`; outputs: `check_output_units`, *then* schema/freq check what the caller receives. That order is the reason it replaced the stackable per-domain decorators; don't split it back up. It takes no options, and reads through `declarations_from_signature`.
- **Tools get `enforce`'s rules from `_contract.py`, and no graph code lives here** — `enforce`, `check_declared` and `declaration_violations` share `_facet_checks`, so a pre-flight cannot drift from a real run; `declaration_conflicts` compares two `Declared`s, with units conflicting unless equal, as `units_compatible` alone passes `Pa` against `hPa` where `enforce` raises. Walking a graph and propagating declarations across nodes belongs to the tool (catena's `contract_check.py`).
- **Root `__init__.py` imports subpackages, never re-exports domain names except the markers** — `from xarray_annotated import units; units.check_units`. Checker names stay put. Exceptions: cross-domain names (`ContractError`, `enforce`, `enabled`, `resolve_enabled`, `annotate`, `declaration_from_hint`, `declarations_from_signature`, `assert_valid_declaration`, `check_declared`, `declaration_conflicts`, `declaration_violations`) and the markers (`Coords`, `Dims`, `Dtype`, `Freq`, `Unit`), which are unique and mixed in one hint. A new domain's marker joins the root too (`test_public_api.py:TestMarkersAtRoot`). Docs import markers from the root.

## Conventions

- **Docs**: zensical (`zensical.toml`) with mkdocstrings, Google-style docstrings. API pages use `::: xarray_annotated.units` directive.
- **ADRs**: `docs/adr/`, for developers. `exclude_docs` in `zensical.toml` keeps them off the site, so user-facing pages must not link to them; `tests/test_docs.py` still runs their `python` fences.
- **Doctests**: embedded in docstrings; `just doctest`.
- **Docs snippets are tested** (`tests/test_docs.py`): every `python` fence in `docs/` and the README runs, per page, top to bottom, on the default registry. Mark a fragment with `<!-- docs-test: skip -->` and a deliberate failure with `<!-- docs-test: raises SomeError -->` on the line before the fence.
- **Examples**: `examples/notebook.py` is a marimo notebook; `just docs` exports to `docs/example.md` via `marimo-md-export`.
- **Formatting**: ruff (line-length 88), pyright, Python ≥3.12.
- **`notes/` is gitignored on purpose** — a local working area (`plans/`, `logs/`, `upstream_issues/`), not part of the package. Write there freely, but never `git add -f` it, and don't mistake its absence from a clone for something missing. Committed files may still reference it: the pointer is for whoever has the tree, not for the repo.
