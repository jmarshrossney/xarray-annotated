## Gotchas

- **No `from __future__ import annotations`** — stringizes annotations, so `get_type_hints` re-evaluates them at decoration; markers survive at module scope, but a function-local alias or `TYPE_CHECKING`-only name raises `NameError`. Not silent, and Python 3.14's deferred annotations do not lift the `TYPE_CHECKING` case.
- **pint registry is process-global** — `use_cf_units()`/`set_registry()` is one-time startup; two registries can't mix. Tests isolate per test via `conftest.py:_isolate_registry`.
- **No global behaviour config; `enabled` is the only global** — axes resolve marker > `enforce` keyword / `check_*` argument > `DEFAULT_*` in the domain's `_config.py`. Don't add a `set_policy`, a per-axis env var, or anything else that changes behaviour away from the signature: a process-wide setting can loosen checks with nothing at the definition site to show it (guarded by `test_public_api.py:TestNoGlobalBehaviourConfig`). The switch is root `_config.py`: an `xra.enabled(...)` block (a `ContextVar`, so no test isolation needed) beats `XARRAY_ANNOTATED_ENABLED` in both directions. Off is total: no checks, no conversion.
- **Audit trail is `logging`, never a mode or a warning** — loggers `xarray_annotated.{units,schema,temporal}`. INFO = a failed/untestable check let through (anything under `ignore`, though `ignore` is always chosen); DEBUG = chosen or routine, including every conversion (always opted into). Never log at WARNING+ (`test_logging.py:TestQuietByDefault`).
- **`check_units` re-stamps `attrs["units"]`** — pint dequantify writes canonical spelling (e.g. `"pascal"` for `"Pa"`); `check_units` overwrites with declared unit. Bypassing it causes attribute drift.
- **Equal units skip the conversion entirely** — `units_equal(have, declared)` (plain arrays only) returns `da.copy(deep=False)` + restamp. Converting copies the whole buffer, for nothing when the values do not change. Don't "simplify" it back into one path.
- **Converting a plain array never touches its coords** — it goes through `Quantity(da.data, have)`, not `da.pint.quantify()`, which also parses every coord's `units` attr, so a `degrees_north` label would abort the conversion. `quantify({coord: None})` is no way out: it deletes the coord's label.
- **`Freq.freq` stores raw string — never normalise** — pandas `to_offset("W").freqstr` silently becomes `"W-SUN"`. Raw spelling preserves anchoredness. Never store/compare normalised `freqstr`.
- **Only a coord with a `PandasIndex` is a time axis** — `_is_datetime_like` asks `da.xindexes`, so `check_freq` never reads the disk, and scalar, 2-D and aux datetime coords never compete with the real one. A custom index on the axis is a mismatch, as it may leave the coord lazy (`test_temporal.py:test_custom_index_on_the_axis_is_refused_unread`). Errors name the coord and its fix from dtype, shape and index alone (`_why_not_axis`), which is why an unindexed cftime gets generic wording. Never value-based cftime detection or `da.indexes`: the first reads every unindexed object coord, the second casts every index to pandas and raises on a custom one.
- **Mismatch errors are never `ValueError`** — `SchemaError`/`FreqError` extend `Exception` directly. Malformed declaration raises `ValueError` at decoration time so catching mismatch never swallows declaration error.
- **Conversion is opt-in, per declaration: `Unit(..., convert=True)`** — a compatible-but-different input unit raises `ValueError` otherwise. No `enforce` keyword, no `check_units` argument, no global: whether a conversion is correct is a property of the quantity (`g m-2 yr-1` vs `g m-2 d-1` is compatible and wrong). A caller-level opt-in would override a declaration that chose not to convert. Same-unit respellings always pass. Inputs only: `convert` is ignored on an output, so one marker can serve both sides.
- **A conversion clears `.encoding`, on the array only** — packing such as `scale_factor` described the old values and overflows on write, silently corrupting the file. `converted.encoding = {}`, not `drop_encoding()`, which also clears coords. Same-unit paths keep it.
- **`check_units` on dimensional mismatch always raises** — no policy knob; always raises `pint.DimensionalityError` regardless of `convert`. So does a missing/unparseable/over-long input unit (`ValueError`): no `on_missing` axis, no `UnitsWarning`, by design — a never-checked declared unit is indistinguishable downstream from a checked one; prototyping uses `xra.enabled(False)`.
- **Quantified arrays are read via `_quantified_units`, never attrs or `.pint.units`** — a `Quantity` holds its unit in the data and has empty attrs. `.pint.units` goes through `da.data`, which reads a whole lazily opened variable from disk, so the helper asks `da.variable._data` instead (`test_units.py:TestLazyArrays`). `attrs` never wins: `quantify()` *raises* ("Cannot attach units") when a leftover attrs label disagrees, so reading attrs first breaks the pipeline. Inputs come back dequantified+stamped; outputs **stay quantified** (`dequantify()` copies the whole buffer even with nothing to convert). See `notes/logs/2026-07-31-quantified-arrays.md`.
- **`apply_output_units`' return must be used, never discarded** — a label is respelled on a shallow copy, never in place, since a body may return the caller's own array; a quantified array comes back as itself. The decorator writes results onto a shallow copy of a dict or dataclass return, after every field has passed (`_with_fields`), so the caller's object is never changed, even when frozen or holding an `InitVar`; `__post_init__` does not re-run. Never `dataclasses.replace`, which fails on those.
- **`_is_dataarray_type` accepts `array_type` wrappers — never import jaxtyping** — the check is duck-typed so the composition stays structural; a real import would make it a hard dependency (guarded by `test_public_api.py:test_integrations_are_never_imported`). Hence jaxtyping/beartype sit in the **`integrations` dependency group**, not an extra — nothing to install to "enable" it, unlike the `cf` extra which really is imported. jaxtyping's dim strings are positional *size symbols*, not xarray dim names, so `Dims` is not redundant with them.
- **At most one marker of each type per hint** — `_annotations._single_marker` makes `declaration_from_hint` raise `ValueError` on a second `Unit`/`Dims`/`Dtype`/`Coords`/`Freq`, which is what makes `Declared`'s one-slot-per-type shape lossless. Don't relax it to first-wins or collect-all; merge `Coords` names into one marker instead.
- **`enforce` refuses a declared `*args`/`**kwargs`** — the bound value is a tuple or dict, so the declaration could never be checked. It raises at decoration rather than expanding them; the reader still reports them, as they are what the signature says.
- **`enforce` refuses a marker it cannot apply** — a marker inside `tuple`/`list`/`dict`/`Callable`, on a non-`DataArray` base, or in a generic alias (`type F[T] = Annotated[T, Unit("Pa")]`) raises at decoration (`_refuse_stray_markers`): someone wrote it expecting a check. So does a return or field holding a class whose fields carry markers, when `walk_signature` does not read it (`NamedTuple`, `list[R]`, `R1 | R2`, a record nested in a field; `_refuse_unread_fields`); it reads one record, one level deep, through `| None`, aliases, `Annotated` and generic parameters. The reader still returns `None` for these. A `TypedDict` parameter and the non-`DataArray` half of a partly declared union remain silent.
- **The reader sees through unions, `type` aliases and `TypedDict` qualifiers** — `Annotated[DataArray, ...] | None` and `NotRequired[Annotated[...]]` declare, as `Annotated[DataArray | None, ...]` always did. Two declared union members raise `ValueError`. A new wrapper in `typing` needs adding to `_reader._QUALIFIERS`, or it silently declares nothing. `Annotated[Alias, Dims("x")]` merges the markers of a `type` alias in the base slot, inner first (`_flatten_aliases`), since `Annotated` only flattens a nested `Annotated` itself. An alias that contains itself outside a container raises `ValueError` (`_enter_alias`, a per-path set, since one alias may legitimately appear on two branches).
- **`Unit` has one setting** — `Unit(..., convert=)`, on the marker only. `check_units`/`apply_output_units` take `str | Unit`, and `annotate` takes a string as a writer convenience, but a hand-written annotation always spells the marker.
- **One reader, at the root** — `declaration_from_hint`/`declarations_from_signature` return `Declared`, which keeps the markers and their overrides. Domains export no readers (`test_public_api.py:TestReaders`); `_reader.py` is the only code that interprets `Annotated` metadata.
- **Outputs must already match; nothing is stamped or converted** — the author controls the return, so a different, missing or unparseable unit raises, in one rule with no setting. No `on_output`, no `stamp`: the package cannot tell a stale label (`p * 100` keeps `hPa`) from a true one (a forgotten conversion), and a false alarm is loud where a mislabelled result is silent. A correct body that changes the unit states it with `.assign_attrs(units=...)`, which is taken on trust; see #26. A labelled output must never convert, even under `convert=True`: a stale label would apply the arithmetic twice. Anything that is not a `DataArray` passes through, as for inputs, so an optional return can be `None`.
- **A string in `Annotated` is a description, in every domain** — ignored without error, so `Annotated[DataArray, "Pa"]` declares nothing (`test_decorator.py:test_bare_string_declares_nothing`). Only markers declare.
- **`just docs` reporting a failed notebook cell is expected** — `examples/notebook.py` demonstrates a `DimensionalityError` by raising one, so marimo prints "Export was successful, but some cells failed to execute" and the export continues. Not a regression; don't "fix" the example. Check a stashed tree before treating any docs failure as new.

## Design steers

- **New domain facet: touch `_writer.py`, `_reader.py` and `_enforce.py`** — `annotate()` writes facet values → `Annotated`; `declaration_from_hint()` reads one hint → `Declared` (add a slot), which `declarations_from_signature()` drives over a signature. Round-trip exact. In `_enforce.py`, add its check in the wrapper *after* units on both sides; give it a marker override per axis, and an `enforce` keyword only if a whole-function setting is genuinely needed (mismatch severity deliberately has none). Re-export its marker from the root `__init__.py`. No per-domain decorator.
- **New property within domain: follow existing patterns** — Schema's `_CHECKERS` dict dispatches marker type → checker; additive via registry. Each domain mirrors layout: `_annotations.py` / `_check.py` / `_config.py`, flat re-export via `__all__`.
- **`walk_signature` is the shared reader kernel** — `_annotations.walk_signature(func, extract)`. `extract` turns one `Annotated` hint into a payload or `None` (`declaration_from_hint` for the built-in facets); handles `TypedDict`/dataclass/single return shapes once.
- **One decorator, `enforce`, in `_enforce.py`; units always first** — inputs: `check_units` converts, *then* `check_schema`/`check_freq` see the converted array; outputs: `apply_output_units`, *then* schema/freq check what the caller receives. That order is the reason it replaced the stackable per-domain decorators; don't split it back up. Per-function kwargs are `<domain>_<axis>` (`temporal_`, not `freq_`). It reads through `declarations_from_signature`.
- **Root `__init__.py` imports subpackages, never re-exports domain names except the markers** — `from xarray_annotated import units; units.check_units`. Checker/reader/axis-type names collide across domains (`OnMismatch`, ...), so they stay put. Exceptions: cross-domain names (`enforce`, `enabled`, `annotate`, `declaration_from_hint`, `declarations_from_signature`) and the markers (`Coords`, `Dims`, `Dtype`, `Freq`, `Unit`), which are unique and mixed in one hint. A new domain's marker joins the root too (`test_public_api.py:TestMarkersAtRoot`). Docs import markers from the root.

## Conventions

- **Docs**: zensical (`zensical.toml`) with mkdocstrings, Google-style docstrings. API pages use `::: xarray_annotated.units` directive.
- **Doctests**: embedded in docstrings; `just doctest`.
- **Docs snippets are tested** (`tests/test_docs.py`): every `python` fence in `docs/` runs, per page, top to bottom. Fences inside a top-level `=== "Label"` tab run in a separate namespace per label, as linked tabs are alternative versions of the page. Mark a fragment with `<!-- docs-test: skip -->` and a deliberate failure with `<!-- docs-test: raises SomeError -->` on the line before the fence.
- **Examples**: `examples/notebook.py` is a marimo notebook; `just docs` exports to `docs/example.md` via `marimo-md-export`.
- **Formatting**: ruff (line-length 88), pyright, Python ≥3.12.
- **`notes/` is gitignored on purpose** — a local working area (`plans/`, `logs/`, `upstream_issues/`), not part of the package. Write there freely, but never `git add -f` it, and don't mistake its absence from a clone for something missing. Committed files may still reference it: the pointer is for whoever has the tree, not for the repo.
